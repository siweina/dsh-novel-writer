## 0. 工作纪律（每个实现者必读）

1. **先读** `WebUI` 相关规则：`tools/ui-audit-README.md`、`tools/client-src/README.md`、`tools/visual/README.md`。
2. **门禁**（每次提交前全绿）：
   ```bash
   node tools/build-client.mjs          # 改过 tools/client-src/* 后必须先跑
   node tools/build-client.mjs --check
   node tools/ui-audit.mjs lib/client.js   # 必须 PASS
   node test/client-test.mjs
   npm test                              # 全量
   ```
3. **截图自检**：`/data/ui-work/capture.sh <你的仓库目录> <输出目录>`，产物里的 `*-review.png` 是裁好的审阅图，
   也可以看 `*-1268x900.png` / `*-380x900.png`。**每个你改过的视图都要在 1268 和 380 两个宽度下看过**，不许有挤压、竖排徽章、文字被截断。
4. **CSS 硬规矩**（违反即门禁红或面板坏）：只用 `--dsw-*` token（颜色/圆角/阴影）；中性边框 0.5px；用了 `--dsw-elevation-*` 的表面不再加 `--dsw-alias-border-*` 边框；`font-size` 必配 `line-height`；**CSS 模板区（含注释）里不许出现反引号和花括号**；JS 里新代码不加内联 `style`；JS 用到的 `nw*` 类必须在 CSS 里定义。
5. **i18n**：每个新增/修改的 key 在 `zh` 和 `en` 两张表都要改。英文要地道、简短，不要逐字直译。
6. **测试**：测试断言了某些类名/结构（`test/client-test.mjs`、`test/ui-structure-test.mjs` 的 B2.1「测试命脉 11 类」等）。
   如果改版必须动到它们：**同步更新断言并在提交信息里写清楚为什么**；不许为了变绿而删掉行为断言（例如剪贴板三条降级路径、reqId 过期丢弃、二次确认、hook 稳定性）。
7. **不碰** controller 的 `api.*` 方法签名与语义；新增纯 UI 状态（如某个折叠区是否展开）可以加，但必须在初始 state 给默认值。
8. 用 `git commit` 小步提交，提交信息用中文、写清改了什么。不要 push。

## 1. 设计原则

- **一个页面只讲一件事**：标题告诉你在哪，正文只放这一页的内容。不重复显示全局状态。
- **安静的默认态**：开着的开关不需要整行变蓝、也不需要再贴「已开启」——开关本身就是状态。颜色只用来表达「需要注意」（警告/危险/错误）和「唯一主操作」。
- **说人话**：描述写「对你有什么用」，不写「内部怎么实现」。工具 ID（`novel_xxx`）、参数（`action=audit`）、内部术语不进主文案，最多放进「说明」展开区或 tooltip。
- **一种卡片、一种行、一种分区标题**：全面板只用这三种积木搭页面，不再出现虚线框、无阴影框、蓝色胶囊标题等第 N 种容器。
- **路径和维护信息往下沉**：文件路径、数据目录、state.json 这类「出问题时才看」的信息，统一收进页面底部的「存储位置」折叠区。

## 2. 视觉系统（全局，Foundation 阶段实现）

### 2.1 面板外壳

- **主页标题栏**：左侧「写作助手」+ 状态小圆点胶囊（`● 已启用` 绿色 / `● 已停用` 灰色，用 token 色）；右侧刷新按钮（图标按钮，带 aria-label/tooltip「刷新」）+ 关闭（如有）。
- **子页标题栏**：左侧是「‹ 写作助手」可点击返回（= 原来的返回按钮，**删除正文里单独的「返回」按钮**）+ 分隔 + 当前页标题（粗体）。右侧同主页。
- **删除每页都有的大 Hero 卡片**（「写作助手功能已启用 / 20 个工具…」）。主页把这句一行副标题放到标题下方（小号灰字），子页不显示。
- **删除子页正文里的蓝色胶囊页标题**（如「工具开关」「风格基线」pill）——标题栏已经说了。页面说明如有必要，保留**一行**灰字导语，放在内容顶部。
- 全局提示条（保存失败 / 宿主不可达 / 书库根有问题）保留，样式统一为 Note（见 2.4）。
- 「更新检查失败（上次成功…）」不再占一整条盒子：降级为主页最底部 footer 的一行小灰字；**有新版本**时才在主页顶部显示一条低调的 accent Note「发现新版本 vX，查看 ›」。

### 2.2 分区标题（SectionTitle）

- 不再是蓝色胶囊 + 横线。改为：12px/18px、`--dsw-alias-label-tertiary` 色、字重 600、上间距 24px、下间距 8px、左对齐、与卡片内文字左缘对齐。
- 结构断言要求的 `nwKicker` / `nwKickerRow` / `nwKickerRule` 类名可以保留（只改样式），`nwKickerRule` 可以设为不可见或删掉并同步测试。

### 2.3 卡片与行

- **卡片**：只用 `GroupCard`（`.nwGCard`：radius-xl、elevation-soft、无边框、layer-2 底）。卡片之间 12px。
- **行（PreferenceRow）**：
  - 最小高度 56px，左右内边距 16px，行间用 0.5px 分隔线（已有 RowDivider）且分隔线从文字左缘开始（缩进，不顶到卡片边）。
  - 图标：20px 线性图标，放在 32px 的浅色圆角方块里（现有 nwPrefIcon 可沿用，但统一为一个尺寸）。**同一卡片内要么每行都有图标，要么都没有**。
  - 标题 14px/22px 字重 500；摘要 12.5px/18px 次要色，**最多 2 行**（CSS line-clamp），文案目标是 1 行。
  - 尾部控件右对齐、垂直居中，不换行；在 380px 宽度下控件可以换到标题下方（整行宽），但不许被挤成竖排。
  - **删除 `nwRowOn` 的蓝色底色效果**（类名可以保留为无样式或删除并同步测试）。**删除开关旁边的「已开启/已关闭」徽章**（CountBadge 在开关场景下不再用）。
  - 导航行（进入子页的行）：尾部是「计数（可选） + ›」。计数用中性灰胶囊，如 `6/7`，不用蓝色。
- **危险行**（非净化模式）：不再整行粉红底。用普通行 + 标题前一个小的 `18+` 红色描边标签（文字标签，不用 🔞 emoji）+ 摘要一行灰字。打开后摘要下方出现一条 warn Note。
- **按钮**：每页最多一个 Primary（实心品牌色）。其余用 Ghost/默认按钮。「打开文件夹 / 复制路径」改成小号图标+文字的 ghost 按钮（高度 28px），不是大号白按钮。

### 2.4 Note（提示）

统一四种：`nwNote`（默认灰底）、`nwNoteAccent`（品牌浅色）、`nwNoteWarn`（警告浅色）、`nwNoteDanger` 或沿用现有 `nwPlotErr` 作为错误。全部 radius-md、内边距 10px 12px、12.5px/18px。**不许把原始错误串（如 `book is required`）直接给用户**：要映射成人话（如「先在上面选择一本书」），原始信息可以放在灰色小字里。

### 2.5 图标与 emoji

- 界面里的**标题、按钮、分组名不再使用彩色 emoji**（📊 🎨 🎯 📕 💾 📢 🔞 ✍ 🌐 📋 🎬 等）。统一用现有线性图标集（`nwIconEls` / ICONS，在 `tools/client-src/V6-icons-*.js`）。缺图标就在图标源里补一个（同风格：24 网格、1.5 线宽、currentColor），然后 build。
- 每个工具行要有**有意义**的图标（或者整组不放图标）；不要全部是同一个文件夹图标。
- 用户自己填的内容（书名等）前面不加 emoji。

### 2.6 存储位置折叠区（新组件 StorageDisclosure）

- 新增一个手写组件（放在手写区，与 GroupCard 等同级），接收 `[{ label, path, revealKey }]`，渲染为页面底部的一张卡片：标题行「存储位置」+ `›/⌄`，默认**折叠**；展开后每条一行：label（灰）、path（等宽小字、可选中、超长时中间省略或换行）、右侧两个小 ghost 按钮「打开」「复制」。
- 复用 controller 里现有的 reveal / copy 方法与它们的降级逻辑，**不要重写剪贴板逻辑**。
- 所有页面里原本内联的「XX 存储：路径 + 打开文件夹 + 复制路径」块都改成这个组件，并且**一个页面只出现一次**（在最底部）。

### 2.7 间距与排版

8px 栅格。页面左右内边距沿用 `.nwPanelMain`。分区之间 24px，卡片内边距 16px，行内图标与文字间距 12px。正文字号不小于 12px。

## 3. 信息架构

### 3.1 主页（view=main）——解决「功能难找」

自上而下：

1. 标题栏 + 一行副标题（「20 个工具 · 本地运行，正文不外传」，数字现算）。
2. （条件）全局提示 Note、新版本 Note。
3. **总开关卡片**（单独一张卡片，单行）：图标 + 「启用写作助手」+ 摘要「关闭后所有分析和自检都不会运行」+ 开关。
4. 分区「写作资料」（每本书的创作资料，最常用，放最前）：一张卡片，三个导航行
   - 原创设定（view=creation）——「每本书的世界观、角色和禁忌，写作时自动参考」
   - 必用词表（view=lexicon）——「专有名词和惯用说法，让 AI 不乱换词」，计数=条目数（如果 state 里已有；没有就不显示计数，不要为计数新增请求）
   - 风格基线（view=baseline）——「设定新章节文风允许偏离原作多少」
   - 卡片底部附一行书库概况（小灰字）：「书库 3 部 · 13 章 · 5.0 万字」，点击展开每本书一行（书名、章数、字数、`7 天未动` 灰字）。原来的「书库统计」独立卡片删除。
5. 分区「AI 行为」：一张卡片
   - 分析作品时自动使用（开关）——「AI 分析你的作品时，顺带给出句式分析」
   - 精简工作流（开关）——「AI 只在你要求时才用工具，更省 token，适合长篇」
   - 提示词详细程度（分段：关闭 / 精简 / 完整）——「告诉 AI 怎么用这个插件：不说 / 一句话 / 完整说明」
   - 提示词场景（分段：通用/写新章/改稿/审计/建资料）——**仅在「完整」时显示**；摘要「完整说明按哪种工作来写」。非完整时整行不渲染（如测试断言该行恒在，可改为 disabled 呈现 + 一行「切到『完整』后生效」，二选一，以测试与可用性取舍，在提交信息里说明）。
6. 分区「功能与工具」：一张卡片，导航行
   - 功能开关（view=features，计数 `开启数/总数`）——「情感分析、题材检测、语义增强等分析能力」
   - 工具开关（view=tools，计数 `开启数/总数`）——「控制 AI 能调用哪些工具」
   - 语义模型（view=model）——「本地语义检索模型：可用 · 未加载」（状态现算，沿用 engineStatusText）。**这是新增的主页入口**，原来只能从功能开关页里找到。
7. 分区「记录与维护」：一张卡片，导航行
   - 报告历史（view=reports，计数=报告数如已知）——「已保存的句式分析和风格报告」（入口 onClick 的数据拉取逻辑必须保留）
   - 诊断报告（view=diagnose）——「出问题时生成一份可安全分享的报告」
   - 体验演示（保持原交互）——「用示例文本看看六维文笔分析，不保存任何内容」
8. 分区「高级」：一张卡片
   - 非净化模式（危险行，见 2.3）
9. **存储位置折叠区**：数据目录（含占用大小）、开关状态文件 state.json。
10. footer 一行小灰字：版本检查状态（失败时「更新检查失败 · 上次成功 2026/10/17 08:48」）。

### 3.2 子页（简述，详细做法见各分工）

- **功能开关**：一张卡片列出所有功能开关行；「语义增强」行的「管理」改成行尾的「模型设置 ›」文字按钮。分组如果有天然分组可以拆两张卡片并加分区标题。
- **工具开关**：每个分类一张卡片；卡片头 = 分类名 + `开启数/总数` + 「全部」开关（替代 checkbox，若测试强依赖 checkbox 可保留 checkbox 但样式对齐）；分类默认展开或保持现状，但**行内不再穿插存储路径块**，路径全部进底部 StorageDisclosure。修 i18n 缺失：`tool.novel_diagnose` / `tool.novel_diagnose.desc` 当前显示为原始 key。工具描述一行人话。
- **语义模型**：顶部一张状态卡（状态 + 一句解释），下面子功能开关卡，底部存储位置。
- **原创设定 / 编辑设定**：列表行 = 书名 + 一行「已填 3/6 项」或「未填写，全部交给 AI 决定」+ 尾部「编辑 ›」；「默认设定」行置顶并有说明；新建 = 输入框 + 一个 Primary 按钮在同一行。编辑表单：字段标签不带 emoji，每个字段下有一行灰色帮助文字（示例放 placeholder），底部操作栏：Primary「保存」+ Ghost「清空」（清空要二次确认，沿用现有逻辑）。
- **风格基线**：删掉调试残留 `v3.0.0-UI3`；未选书时显示空态「先选择一本书」，而不是原始错误；顶部一张卡：当前书（下拉）+ 范围（分段：全书/按部分）+ 保存按钮（唯一 Primary，放卡片底部右侧）；六维容差：一张卡片，每维一行，**对齐的网格列**：指标名（+ ? tooltip 解释）｜「低于」输入 %｜「高于」输入 %｜（可选）滑块；不许再有游离的 `-` `~` `%` 字符。
- **必用词表**：顶部设置卡（当前书、作用层分段、强制注入开关、本层生效开关）；**词条列表放在表单之前**（搜索 + 列表）；「新增词条」是一个按钮，点开后才出现表单卡（编辑某条时同样展开表单并滚动到它）；「批量导入」做成次要按钮/折叠区；「书库根」设置移入底部「高级」折叠区或 StorageDisclosure 旁；`novel_lexicon（action=audit）` 这类提示改成人话「写完后让 AI 检查一遍用词，就能看到哪里用了替代词」。
- **报告历史**：按书分组（每本书一张卡片或一个可折叠分组，组头显示书名 + 报告数）；报告名友好化：`__base-full` →「全书基线」、`-chapters-metrics` →「逐章指标」、`-full` →「全书分析」、`-keywords-xxxx` →「关键词」、纯哈希 →「单段分析」+ 哈希前 6 位灰字；日期右对齐灰字。友好化只在展示层做，点击打开的仍是原文件。
- **诊断报告**：统计窗口卡 + 「值得注意」卡（修复第一行几乎看不见的问题）+ 报告正文（等宽滚动块）+ 底部按钮（重新生成=Primary，复制诊断包=Ghost）。把 `diagnose` 加进 `tools/visual` 的 VIEWS（README 写了怎么加）。

## 4. 文案风格（zh）

- 动词开头或直接说结果，主语是「AI」或「你」。
- 一句话 ≤ 30 字；超过就拆，长解释进「说明」展开区或 tooltip。
- 不出现：工具 ID、参数名、文件名（除了存储位置区）、版本号、「骨/皮」这类内部比喻。
- 术语首次出现给白话：「六维文笔指标」→「文风六项指标（句长、修饰、抽象度…）」。
- en：同样短句；术语统一（Style baseline / Lexicon / Creation profile / Diagnostics / Reports / Semantic model）。

## 5. 分工与合并

- Foundation（先做，单人）：第 2 节全部 + 3.1 主页 + 外壳。在分支 `ui-refactor` 上提交。
- 之后三路并行（各自 git worktree + 分支，基于 Foundation 提交）：
  - A：功能开关 / 工具开关 / 语义模型
  - B：必用词表 / 原创设定 / 编辑设定
  - C：风格基线 / 报告历史 / 诊断报告
- 并行期约定：**只改自己视图的渲染分支**和自己前缀的 i18n key；共享组件（PreferenceRow / GroupCard / StorageDisclosure / SectionTitle / 图标）**不改接口**，确有需要在提交信息里提出，由设计负责人合并时统一处理。
  新 CSS 写进 `tools/client-src/V6-components.css` 里属于自己的锚点注释段（Foundation 会预置三个锚点：`v7-A`、`v7-B`、`v7-C`），然后 build。
