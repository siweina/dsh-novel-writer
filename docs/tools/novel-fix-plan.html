novel_fix_plan

v6.1.0：plan 仍最多展示并保存 12 项；verify 使用未按该上限截断的检测全集比较，不把被高优先级问题挤出的旧项误判已解决。
v6.1.0：章节参数先精确匹配完整文件名，再匹配省略扩展名的文件名；同名多扩展名时必须提供完整文件名，明确指定却不存在的扩展名不会改读另一格式。
v6.5.0：字面类待办（禁用词 / 语用不符）改为行号区间定位，并跳过子串巧合（与 novel_continuity_check 的用语审计同一套邻接守卫）；2 字词标为待判档，读原文后判定只是相邻巧合即可 mark state: "skip"。
v6.5.5：指标类待办的基线改为可配置——面板「风格基线」的基线范围（按全书 默认，＝旧行为；按部分 只用勾选的章，按书存储）决定「跟谁比」。目标章永远排除（即使被勾选）；实际参与 μ/σ 的基线章少于 3 章时容差下限抬到 ±25%；勾选的章一章都取不到时回退按全书（绝不以空基线出结论）。范围由 baselineScope（文案）/ baselineMode（档位）两个键披露，文案也写进 summary 与落盘清单。
v7.0.0：新增三类待办——AI套话（类别 8→9：同一类别下的多处命中合成一条，给命中处数与行号区间，target 是「0 处」，不罗列套话原文以免负样本诱发）、原地打转与大纲漏写（9→11，本地向量审计，只在改稿台跑）。
v7.2.0：新增对抗性审计三个动作——audit 严格对账 / audit_brief 生成独立 AI 任务书 / audit_verify 复核它交回的取证。工具数仍为 22：能力挂在既有工具上，不新增工具。三件事说清楚：① 动作取值从三个变成六个（参数表只多一个 claims）；② 审计只报能举证的违约——每条违约要么落到 1-based 行号与原句片段，要么明确标成全章层面（line: 0）并指向哪张表 / 哪条子句没对上；detail 只写「事实 + 依据」，不评价文笔（抽象度 / 物件偏少 / 感官单通道这类风格症状仍在改稿台与开写包里作建议，但不进审计）；③ 独立 AI 的结论必须原样回传复核：行号错但原文确实在文中 → 自动修正（corrected），原文在正文里根本不存在 → 判为编造证据（rejected）并计入废卷。三个动作都不改正文、不落盘，也不受「写作助手功能」总开关约束（对账是对契约，不是对文风）。

改稿台。把某一章的测量偏差翻译成按优先级排好序的待办清单：每项带稳定 id、类型、原文定位（lineStart / lineEnd / excerpt）、现值与目标区间、可照改的原著锚段、严重度与改写代价，以及一句改写方向。action: "plan" 出清单，"verify" 复测，"mark" 标记单项。工具本身从不生成改写后的正文句子。指标类待办「跟谁比」由面板的基线范围决定（默认按全书，可改成按部分、只用勾选的章）。

v7.2.0 起同一个工具还挂着对抗性审计：action: "audit" 严格对账（只报能举证的违约：行号 + 原句，或明确标注的全章层面）、"audit_brief" 生成给另一个没有写作上下文的 AI 的任务书、"audit_verify" 逐条复核它交回来的取证（行号错但原文在文中 = 自动修正，原文查不到 = 疑似编造证据、判废）。审计不评价文笔、不修改正文、不落盘——它不是文学评论，是账。

为什么要有它。novel_style_check 返回的是数据——偏差清单、六维判定、原著锚段与一个 verdict 分级；它没有说「所以先改哪一句」。把数据组织成行动是模型的额外工作，而工作一旦靠自觉完成，就会时做时不做。本工具把同一批测量结果直接翻译成待办：排序由 severity / effort 决定，位置由行号给出，改完用 verify 复测，形成 plan → 改 → verify 的闭环。
关键边界：hint 只给方向，不给正文。每项的 hint 是一句改写方向（如「这句抽象词过密，改成具体动作或物件」），而不是改写后的句子。生成正文是宿主模型的事，插件不做——这是本插件的立身之本：零 token、正文不出本机。任何把 hint 当作「可直接粘贴的成稿」的用法都偏离了契约。

参数

参数类型必填说明
bookstring是书名，即 novels/ 下的子目录名。空串或纯空白被拒绝，值经 sanitizeSegment 清洗。
chapterstring是要改的章节标识：章号（1 / 01）、文件名（第01章.md）或标题子串，由 findChapter 解析；找不到则报错。与 novel_style_check 同一套解析规则（文件名优先于章号、纯数字不做子串兜底）。
actionstring否枚举 "plan"（默认，产出待办清单） / "verify"（复测） / "mark"（标记单项） / "audit"（严格对账：只跑可机器判定的契约，每条违约带行号与原文） / "audit_brief"（生成给独立 AI 的审计任务书） / "audit_verify"（复核审计者交回的 claims）。省略或非枚举取值时按 plan 处理。
itemIdstringmark 必填mark 必需：目标待办项的 id（取自 plan 返回的 items[].id），必须已存在于该章已落盘的清单里。缺省或空白串直接报错。
statestringmark 必填mark 必需：处置状态，枚举 "done"（已按 hint 改过） / "skip"（有意不改）。缺省或非枚举值直接报错，且两种情形文案不同（v5.0.0 修正）：未传 → 「缺少 state 参数：只能是 "done"（已改）或 "skip"（跳过不改）」；传了非法值 → 「state 只能是 "done"（已改）或 "skip"（跳过不改），收到："finished"」。（旧版两种情形都报「需要 state 参数」，传了非法值时容易被误判成漏传。）
claimsarrayaudit_verify 必填audit_verify 必需：审计者交回的声明数组，每条形如 { contract, line, text, why }——contract 是契约 id（audit 返回的 contracts[].id 之一）、line 是 1-based 行号、text 必须是该行原文的连续子串（不得改字、不得拼接、不得跨行）、why 是可选的 ≤40 字理由。条目上声明 additionalProperties: false，必填项为 contract / line / text（why 可省）。插件会逐条复核：编造的行号与原文会被判 rejected。省略或非数组时按「没有待复核的声明」处理（total: 0），不报错。
rootstring否章节库根目录。省略时按 config.root → 会话工作目录回退；MCP 形态下越界值被静默回退到启动参数 --root 指定的书库根。

参数对象声明 additionalProperties: false。本工具没有阈值类可调参数：严重度权重、类型判据与截断上限都是常量（截断上限恒为 12 条，v5.1.0 起由 40 收紧到 12）。测量入口 buildFixPlan / verifyFixPlan 自身接受 opts.tolerance / opts.maxItems / opts.plotStaleChapters 三个内部选项，但工具层固定传 {}，不对调用方暴露。

action 取值

取值语义前置要求返回体形态
plan重新测量本章并产出待办清单（默认），同时把清单原子写到该章的 fix-plan-*.json。章节可解析；写作助手功能已开启（六维引擎门禁，与 novel_style_check 同口径）items[] + summary + planFile
verify对当前正文重算，并与上次落盘的清单逐项比对，给出三态结论。不写盘。同上（引擎门禁）；清单文件不存在时不报错，改为报告「按当前正文现算」checked[]（逐项三态）+ summary
mark把单项标记为已处置（state: "done" 已改 / state: "skip" 有意不改）。只改落盘清单里的处置状态，不重新测量、不改正文，因此不受六维引擎门禁约束。itemId 且 state 齐备，且该章已有落盘清单、itemId 能在清单里找到ok + item（被更新的那条）
audit（v7.2.0）严格对账：只跑八条可机器判定的契约，每条违约都带 1-based 行号与原句片段；不评价文笔、不改正文。没跑的契约会写明原因（ran: false + reason），不把「没查」伪装成「查过没问题」。只读，不落盘。章节文件可解析；不依赖六维引擎、也不受「写作助手功能」总开关约束（两条向量契约要看本地语义引擎是否可用，不可用时该契约 ran: false）auditReport（结构见下文）+ summary + ok
audit_brief（v7.2.0）出任务书：生成一段 Markdown 交给没有写作上下文的 AI——写清允许的契约与判据、取证 JSON 格式、「举不出证据一条都不许写」的硬约束，末尾附本章正文（行号从 1 开始）。不派 AI、不发网络请求（插件是工具提供者，spawn 子代理是宿主的事）。同上；正文会整段进入返回体（返回体大小约等于正文长度）auditBrief（结构见下文）+ summary + ok
audit_verify（v7.2.0）复核取证：把审计者交回的 claims 逐条验证——都对 → accepted；行号错但原文在文中别处 → corrected（自动修正行号）；全文找不到 → rejected（疑似编造证据）。最后给 score（可信证据占比）。只验存在性，不判断「算不算违约」。claims 为数组；章节正文可读（行号以它为准）。claims 缺失/空数组不报错，返回 total: 0auditVerify（结构见下文）+ summary + ok
门禁口径：mark 与 plan / verify 不同。plan / verify 依赖六维引擎，执行前先读状态文件里的「写作助手功能」总开关，关闭时直接拒绝执行（与 novel_style_check 完全一致）。mark 在引擎门禁之前就分支返回——它只是读-改-写自己那份清单，即使总开关被关闭也能用来登记处置状态。三个改稿动作（plan / verify / mark）都仍要过工具级开关 assertToolEnabled("novel_fix_plan")。
v7.2.0：审计的三个动作同样不受「写作助手功能」总开关约束。audit / audit_brief / audit_verify 在引擎门禁之前就分支返回——对账是对契约（词表、登记表、结构），不是对文风，因此总开关关着时仍能对账。它们仍要过工具级开关。

六个动作的返回体形状并不相同，且只有 plan 返回 planFile：

audit_brief（v7.2.0）book、action、chapter、summary、ok、auditBrief——brief 是给没有写作上下文的 AI 的整段任务书（末尾附正文）、allowedContracts 是允许的契约 id、protocol 是同一份约束的机器可读版本

chapter 对象来自目录扫描：number 解析不出时为 null（键被整键丢弃）。契约必返字段是 book / action / summary。

items[] 条目

实现里的 makeItem 严格只产出下列 9 个字段，条目 schema 为 additionalProperties: false——落盘文件里额外追加的 state / stateAt 属文件内部字段，不出现在返回体。

字段类型内容
idstring稳定 id，形如 fix-<类型 slug>-<lineStart>-<sha1 前 8 位>。sha1 由 类型 | key | lineStart | lineEnd 派生（key 是指标名、word:词、honor:词、ritual:模式、title:sister、bridge:候选类型、plot:伏笔 id 等内部键）。同一章同一位置重新 plan 必得同一个 id，因此 mark 与跨次 verify 都能对齐同一项；正文改动导致行号变化时 id 随之变化。
typestring十一类之一（中文，取自 METRIC_TYPE 与各 collect*Items）：句式偏离 / 抽象度过高 / 留白异常 / 禁用词 / 语用不符 / 衔接缺失 / 伏笔未回收 / 情感过直 / AI套话（v7.0.0）/ 原地打转（v7.0.0）/ 大纲漏写（v7.0.0）。
locateobject{ lineStart, lineEnd, excerpt }：段落的绝对行号区间（1 起，含空行计数）与该段原文节选（截 80 字）。lineStart = lineEnd = 0 表示该问题属全章 / 跨章层面、定位不到具体行。
currentstring当前实测值或命中描述。指标类为「维度名 + 实测值」（如 complexity 0.61）；禁用词为「命中「词」N 处（位置：第2-10行，第52行）」；语用项为「客套禁词「词」N 处（位置：…）」/「仪式禁式「样本」N 处（位置：…）」/「称谓「XX小姐」（位置：第N行）」；情感过直为「情绪直陈 N 处（全章 M 处）」；衔接缺失为候选类型名；伏笔未回收为「未回收 N 章（最近提及：…）」。字面类的位置是可能不连续的多个区间（第2-10行，第52行）；locate.lineStart / lineEnd 取首段起点与末段终点，是这些区间的超集——精确处看本字段。
targetstring目标区间或目标状态。指标类为基线带 low~high（如 0.38~0.52；基线 μ = 0 时为空串）；禁用词为「改用「替代词」」或「避免使用该词」；衔接缺失为「补过渡/承接句（1 句即可）」；其余类别可能为空串。
anchorstring可照改的原著锚段（源自 buildStyleAnchorPackage 的抽样结果，与 novel_style_check 的 fixAnchors 同源；抽样语料同样按面板「基线范围」选取并排除本章）。只有指标类与 AI套话会带锚段（后者的 anchor 是一句类别说明，不是原著样例），其余类别为空串。
severityinteger严重度 1–5（超出范围会被钳到边界）。指标类按 |σ| 分档：≥ 3σ → 5、≥ 2σ → 4、其余出带 → 3；退化成「全章层面」的指标项再降一档（max(1, sev-1)）。其余类别为固定值：禁用词 4、客套禁词 4、仪式禁式 4、称谓 3、情感过直 3、衔接缺失 2–4（时间硬跳 4 / 检查跳过 2 / 其余 3）、伏笔未回收 3–4（距离 ≥ 40 章或 priority: "high" → 4）。
effortinteger改写代价 1–3（超出范围会被钳到边界）：1 = 局部替换即可（有登记替代词的禁用词 / 客套词；衔接缺失里的时间跳跃 / 时间过渡 / 钩子未接），2 = 需要重写该句或该段（指标类段落项、情感过直、仪式禁式、称谓；衔接缺失里的语义距离 / 人物断线），3 = 需要通读全章或跨章处理（指标类的全章层面项、伏笔未回收；衔接缺失里的检查跳过）。同严重度时先做省事的项。
hintstring规则拼接的改写方向（一句话，含实测值与基线的对照，指标类还会带上「本段 X」与方向建议），例如「抽象度偏离：全章 41（基线 22，偏差 +86%），本段 48。这句抽象词过密，改成具体动作或物件。只改这一段的写法，不要整章重写。」不含改写后的正文句子。
软化后缀（v5.1.0 新增，只有三类带）：abstractDensity 抽象度 / gapIndex 留白指数 / hedgeDensity 不确定性三类指标的 hint，在原有前缀之后追加一句「（仅当这里读起来确实别扭才改；抒情、心理、留白段落属正常写法，可标记 skip 保留。）」。hint 前缀格式未变，只是句尾多这一句——它把这三维的默认处置从「改了」改成「先判断再决定」，抒情 / 心理 / 留白段落本来就该在这三维上偏离全书均值。
档位前缀（v6.5.0 新增，只有字面类带）：禁用词 / 客套禁词的 hint 以 【硬命中·3字以上】 或 【待判·2字词】 开头。档位只在这一句里表达——type 字符串按契约不变（见「十一类待办的判定来源」）。待判档必须给出「可以不改」的出口：句尾追加「…请读第2-10行自行判断：若确为该词就改；若读该行发现只是相邻巧合，可跳过本项（mark state="skip"），并说明判断依据。」，否则会退化成一律照改。

排序

sort(items) = severity 降序 → effort 升序 → lineStart 升序 → id 字典序

四级排序的用意依次是：先改影响文风判定最严重的；同严重度时先做便宜的（不让人卡在难改的一段上）；同权重同代价时按正文顺序自上而下，便于一次通读改完；最后一级只用于让完全同键的项结果可复现。lineStart = 0 的全章层面项排在同键项的最前（行号最小），调用方应显式分支处理，不要把它当作「第一段」。

渲染文本带 id（v5.0.0 修正）：plan 的渲染在每条待办的「类型 / 严重度 / 难度 / 位置」行下方紧跟一行 id：fix-…。此前 id 只在返回体与落盘文件里，模型要 mark 得先自己去读 planFile 才能拿到——现在清单里直接可复制，少一次往返。

渲染文本带「处理建议」（v5.1.0 新增）：plan 的渲染在 待办 N 条… 之后多一行处理建议，内容是分批改——同一段落 / 同一类型的问题合并成一次修改；一轮只处理 3~5 条；不必逐条 mark；改完最多 verify 一次。这是给调用方的节奏约束，不是新的返回字段：返回体形状未变（items[] 仍是 9 字段，state / stateAt 仍只落盘、只由 mark 写入）。改稿一次只动几处、一次改完整段，比按清单从上到下逐条打磨更接近真实改稿，也能避免「改一处、测一次」的往返成本把注意力耗在数字上。清单上有一条不等于必须改那一条：只有偏离达到 2 倍容差以上、或那一处读起来确实别扭时才动笔——容差带本身取 1.5σ，六维里有一维出带是常见现象，为对齐数字改文只会把作者的写法磨平；确实属于正常写法的（抒情 / 心理 / 留白段落）用 mark state: "skip" 留下记录即可。

三个审计动作各自只产出一个专属键，彼此不混装；三者都只读：不改正文、不写盘、不迁移旧数据（读 novel_plot 的登记表时走 readOnly 分支，避免顺手把旧位置伏笔表搬到新位置）。

auditReport（action: "audit"）

auditReport = { file, // 章节文件名（basename，不是完整路径） chapterNumber, // 由文件名解析；解析不出为 null，且被整键丢弃（返回体里不出现该键） lines, // 正文行数（空正文 0 行；与 novel_read / countTextLines 同口径） contracts: [ { id, label, ran, reason? } × 8 ], // 恒 8 条，顺序固定，不按有无违约过滤 violations: [ { contract, severity, title, line, text, detail } ], // 每条恒 6 键 summary }
  • contracts 恒 8 条（lexicon / banned / slop / loop / outline / ending / bare_dialogue / plot，顺序即定义顺序）。ran: false 的条目带 reason（如「未登记必用词表」「语义引擎不可用」）——它表示「没查」，不表示「查过没问题」。
  • violations 每条恒 6 键：即使注入的依赖多给了字段也不许漏进输出（审计的契约是「无建议性字段」）。title 为空时回落到契约 label；severity 钳到 1–5 的整数；line 为 1-based 行号，0 表示全章 / 跨章层面（此时 text 通常是空串）；detail 只写事实与依据，不写改法。
  • 排序：severity 降序 → contract 字典升序 → line 升序（lib/audit.js 的 compareViolations）。
  • summary 形态：「严格对账：N 条违约（其中 H 条硬违约）；M 项契约未跑（id：原因；…）」。硬违约 = severity ≥ 4（世界观禁用词、命中 ≥3 处的套话），其余是一般违约。
  • 渲染文本：逐条列出 [契约] 标题（第 N 行 / 全章层面，严重度 S，硬违约 / 待确认），有原文与依据才各起一行；末尾单独列未跑的契约，并固定写一句「审计只报能举证的违约，不改正文、不评价文笔；「硬违约」与「待确认」的区别是后者可能是你有意为之」。0 条违约时的文案是「没有发现能举证的违约。（不等于「文笔没问题」……）」。

auditBrief（action: "audit_brief"）

字段内容
brief给没有写作上下文的 AI 的整段任务书（Markdown，八节）：身份与边界（「你是审计员，不是编辑」）→ 任务 → 允许的契约（逐条判据）→ 取证格式（严格 JSON，带一个示例）→ 硬约束（违反会被判废）→ 输出 → 本次审计对象（书 / 文件 / 章号 / 行数 / 允许的契约）→ 正文（代码围栏，行号从 1 开始，与 line 字段一一对应）。围栏长度按正文里最长的反引号串自适应（至少 3 个），避免正文自带 ``` 时把任务书的正文层提前闭合。任务书只写判据与取证格式，不写任何改法。
allowedContracts本次允许的契约 id 数组。工具层恒为全部 8 个——buildAuditBrief 支持传子集（未知 id 忽略、一个都不剩时退回全量），但调用参数里没有暴露该选项（additionalProperties: false）。
protocol同一份约束的机器可读版本：version: 1、book / file / chapterNumber / lineCount、contracts[]（{ id, label, criterion }）、allowedContracts、claimFields（contract 的 enum、line 的 1..lineCount、text 的「该行连续子串」、why 的 ≤40 字）、outputSchema、verifyRules（textMustBeContinuousSubstring / lineIs1Based / normalizesWhitespace / correctsLineWhenTextFoundElsewhere / rejectsFabricatedText）与 output 示例。

auditVerify（action: "audit_verify"）

auditVerify = { total, // 参与复核的声明数 = accepted + corrected + rejected（去重后） score, // 可信证据占比 = round((accepted + corrected) / total × 100)；total = 0 时为 0 accepted: [ { contract, line, text, why } ], // 行号与原文都对 corrected: [ { contract, line, text, why, foundLine, reason } ], // 行号错、原文在文中别处 rejected: [ { contract, line, text, why, reason } ], // 判废 reason? // 仅 total = 0 时出现：「没有待复核的声明」 }
  • 四条判定：text 去空白后为空、或 line 不是整数 / < 1 / 超出正文行数 → rejected（reason = 「行号或原文缺失」）；该行（空白归一后）包含声明原文 → accepted；该行不含但全章其它行能找到 → corrected（按行号升序取第一条，foundLine 是实际行号，line 仍是声明时给的行号）；全章都找不到 → rejected（reason = 「原文在正文中不存在（疑似编造证据）」）。
  • 去重：同一 contract + 归一后原文只保留第一条；原文为空的非法声明不参与去重（否则多条坏声明会被并成一条，虚高 score）。
  • 空白口径：声明与正文行都先做 \s+ → 单空格、去首尾再比较；再退一步用「去掉全部空白」的形态兜底（容忍独立 AI 多打 / 少打一个空格）。回填的 text 恒为归一空白后的形态（机器可读、稳定）。
  • 不校验的东西：contract 是否在 8 个合法 id 里、why 是否超 40 字——复核只验存在性，判不了「这条算不算违约」。
  • 渲染文本：一行汇总「N 条声明 → 可信 X 条（其中 Y 条行号已修正），判废 Z 条；可信度 score%」，然后分 ✅ 采纳 / ✎ 行号已修正（原文确实在文中，只是行号报错） / ✗ 判废（疑似编造证据，不要采信） 三组列出。

严格对账的 8 条契约（v7.2.0）

action: "audit" 只跑下面这八条可机器判定的契约。判据、severity 与「没跑」的条件都照 lib/audit.js 的 CONTRACT_DEFS 与八条处理器写——判据只写怎么判，不写怎么改：改法是改稿台 hint 的事，不是审计的事。

契约 id判据（一句话）severity未跑（ran: false）的条件
lexicon
必用词/替身词		必用词（含 aliases 等价写法）本章一次都没出现，或出现了词表登记的「通用替身词」（沿用 v7.1.0 的严格包含口径：替身词包含必用词时，如必用词「药」vs 替身「草药」，该处仍算用了替身词）。未出现 2（line: 0、text: ""，全章层面）
替身词 3（取该词条首次出现的行）		「未登记必用词表」；「必用词表文件损坏（无法读取或不是合法 JSON）」。表为空是「没跑」，不是「没问题」
banned
世界观禁用词		正文使用了 core.resolveStyleRule 裁决出的禁用词（本书 allowWords 的逐词静音已在裁决点生效，这里不重复实现）。同一行同一词只报一条。4（恒为硬违约）「未登记世界观条目（worldview）」或「当前文化基准没有可用的禁用词（未登记 bannedWords / 全被 allowWords 豁免）」——空材料一律 ran: false，与 lexicon 同口径（v7.2.0 修正前这里会报 ran: true + 0 违约，看起来像「查过没问题」）
slop
套话		命中套话词表（8 类）的词面片段，按类别归并：每类只出一条，取该类最早命中行，detail 给类别名与命中处数。基准 3；同类 ≥3 处 → 4、≥6 处 → 5（封顶 5）无固定条件——只有该步抛错时才由外层 catch 记为 ran: false，reason 是错误消息
loop
原地打转		连续语义块高度相似且几乎没有新信息（detectSemanticLoop：章内稳健 z 分数 与 绝对余弦 与 词汇新颖度三条件同时满足）。3「语义引擎不可用（模型缺失或 WASM 初始化失败）」；checked !== true（正文 < 200 字、语义块太少、任一嵌入失败——引擎给的 reason 原样透传）
outline
大纲兑现		本章大纲方向行的某个子句，在正文里关键词命中不足且向量相似低于阈值 → 该子句「未兑现」；skipped（查询向量拿不到、压根没判定）不算违约。3（line: 0、text: ""，全章层面）解析不出章号 / 大纲文件不存在或没有本章方向行 / 方向行为空 / 引擎不可用 / checked !== true（方向行过短、正文 < 200 字、切不出语义块、嵌入失败）
ending
章末收束		章末停在抽象感悟 / 预告上（ending_preach 症状）：结尾段没有对话、具体动作 < 2 处，且命中抽象总结词或章末套话。3（line = 最后一个内容行，跳过空行 / Markdown 标题 / 分割线）实际上恒 ran: true——诊断函数内部逐维吞错并返回空数组；只有依赖本身抛错才 ran: false
bare_dialogue
连续裸台词		连续多段只有台词与「道 / 冷笑」，旁白 < 12 字且没有具体动作或器物接触（bare_dialogue）；行号取该游程首段的真实行号（游程由 maxBareDialogueRun 给出，再经语义块定位换算；定不到给 0）。3与 ending 共用同一次诊断，条件同上
plot
伏笔登记		仍 open 且登记章号早于本章的伏笔，本章命中其 ≥2 个关键词，但登记表没记录本章提及 → 「伏笔疑似推进但登记表未更新」。2（刻意只给最低档——「推进」本身不可判定，见下节）「无伏笔记录」（先于章号判定：登记表为空时给这个原因）/「解析不出本章章号，无法核对伏笔登记」
这份表的四条通用规则。
① 顺序即定义顺序，contracts 恒 8 条，不按「有没有违约」过滤；ran: false 的条目带 reason，它表示没查，不表示查过没问题。
② 八条契约各自独立 try/catch：某一条抛错或依赖缺失只让它自己 ran: false，其余照跑；取消（AbortError）一律向外重抛，不伪装成「契约未跑」。
③ 硬违约 = severity ≥ 4：实际上只有 banned（4）与命中密集的 slop（4~5）算硬违约；lexicon 的必用词缺失是 2、plot 是 2，其余一律 3。
④ 行号口径：绝对行号、1-based、\r\n / \r 先归一为 \n（行号不变），与 novel_read 同口径；line: 0 表示全章 / 跨章层面，调用方要显式分支，不要当成「第 1 行」。
口径与改稿台的对齐情况（v7.2.0 发布前修过一轮）。
① banned 的豁免表已与改稿台统一。审计现在用 core.isGuardedArtifact（lib/lexicons/guards.js 的实证碰撞表），与改稿台、连贯性审计同一张。修正前误用了细节密度的六通道搭配表，导致「这里正是…」含禁用词「里正」时改稿台静音、审计报硬违约——两套结论互相打脸，现已消除。
② slop 现在也套用「题材静音」。审计会先用 buildSlopExemptions("", { settings }) 生成豁免（系统流 / 数据面板题材静音 stat_numeric），再 scanSlop。但「参照集高频习惯词」这一层审计不加载（不读基线章）——所以审计只会比改稿台更严，不会更松。
③ 语义开关已透传。features.semanticEmbedding 关闭时，loop / outline 记 ran: false 并写明原因，与改稿台 plan / verify 同口径，不会再绕过用户设置去跑嵌入推理。
④ 空材料语义已统一。lexicon（无词表）与 banned（无可用禁用词）一律 ran: false + 原因；看到 0 违约时先看 ran，别把「没查」读成「查过没问题」。

为什么这不是文学评论（v7.2.0 设计取舍）

写作没有真值。一段文字「好不好」无法用机器判定，任何这类判断都只是模型口味。所以审计的产出只允许是违约：契约必须可判定（词表命中 / 登记项缺失 / 结构性症状），每条违约要么能定位到 1-based 行号与原文片段、要么在明确标成「全章层面」（line: 0）时仍指向具体的表项或大纲子句——不能有任何一条是「我觉得这里不好」，detail 只写「事实 + 依据」，绝不写「应该怎么改」。这条边界也写进了任务书本身——「你是一名审计员，不是编辑」「举不出证据的一条都不许写」。

① 风格症状被明确排除（是取舍，不是漏做）

abstract（抽象度）/ object_thin（物件偏少）/ sense_mono（感官单通道）/ action_thin（动作偏少）这类风格症状不进审计：它们都是「相对参照集分位」的判断，题材差异极大——一旦写成违约，审计就会天天劝人把留白填满、把抒情段改成动作段。它们仍是改稿台与开写包里的建议（那里的处境不同：把选项摆出来，改不改由作者定），只是不会变成「违约」。

代码上还有第二道保险。审计调用 diagnoseChapterSymptoms(text, refStats) 时 refStats 传的是 null，该函数在 refStats = null 时只返回结构性症状（ending_preach / bare_dialogue），相对类症状（abstract / action_thin / sense_mono / object_thin）根本不会产生。套话的词表命中仍是违约（词面事实，由 slop 契约负责），但它的相对分位版本同样不是。

② 只报不改

审计永不修改正文：三个动作都不写文件（不落盘报告、不写清单、不迁移旧数据），detail 里没有改写建议，返回体里没有任何「改写后的句子」。改不改、怎么改由作者决定——插件只负责把账摆出来。

③ 三段式：插件出任务书 → 宿主派独立 AI → 插件复核证据

插件是工具提供者，不能 spawn 子代理，也不调用在线模型。所以一次完整的对抗性审计是三次调用 + 一次宿主动作：

① novel_fix_plan action="audit" → 机器契约直接对账（零 token，只报能举证的） ② novel_fix_plan action="audit_brief" → 出任务书（判据 + 取证格式 + 硬约束 + 正文） └ 宿主把整段 brief 交给一个没有写作上下文的独立 AI（上下文隔离是宿主的责任） ③ novel_fix_plan action="audit_verify" claims=[…] → 逐条复核取证 accepted（都对）/ corrected（行号错、原文在文中）/ rejected（查不到 = 疑似编造证据） → score = 可信证据占比

没有第 ③ 步，前两步只是「第二个会说话的模型」。独立 AI 的结论不是结论，只是一组待验证的声明；能不能采信，由插件逐条核对行号与原文决定。

面板也有独立入口（v7.2.0）。WebUI「诊断报告」页新增一张「对抗性审计」卡片，三个按钮各自标明成本： 「严格对账 · 本地 0 token」「生成任务书 · 0 token」（结果自动复制到剪贴板）「复核证据 · 0 token」（粘贴外部 AI 返回的 claims，当场给出采纳 / 修正 / 判废）。后端对应一条只读路由 /api/dsh-novel-writer/audit （GET 探测并返回作品名清单，面板的书名下拉用它；POST 三种 action；chapter 留空 = 最后一章）。 卡片里还写了「独立 AI 复核」的四步用法（生成任务书 → 派新子代理 → 子代理只回 claims JSON → 粘回来复核）， 以及口径号与插件版本不是一回事的说明（口径号只在测量规则变化时递增）。
为什么单开一个入口而不做成新工具：工具数 22 是跨 MCP 清单、面板开关与文档计数的稳定契约，审计属于「改稿」域， 用动作 + 面板入口即可。而单独放一张卡片是为了把两笔账分开——本地对账零成本、随便点； 「派独立 AI」会产生一次额外会话费用，混在改稿台里会让人以为都免费。

④ 诚实披露局限

  • loop / outline 本质是启发式。它们依赖本地 embedding，报的是「相似度与新颖度没达标」「关键词与向量都没达标」，不是「作者写错了」。引擎不可用（模型缺失 / WASM 失败 / 正文 < 200 字 / 语义块太少 / 嵌入失败）时这两条契约是 ran: false 并写明原因，不是「查过没问题」；outline 的 skipped（查询向量拿不到）既不进未兑现，也不冒充已兑现。
  • plot 的「推进」不可判定。只靠「命中该伏笔 ≥2 个关键词」这一条启发式，关键词少或同名时既会漏、也会误报。所以它 severity 只给 2、标题写「疑似推进但登记表未更新」、line 只指向首个命中关键词的行，detail 里列出命中的关键词，让人自己看。
  • 证据复核只验「存在性」。它能判「这段文字在第几行、是不是真的」，判不了「这条算不算违约」——后者仍要人看一眼。它也不校验 contract 是否属于 8 个合法 id、不校验 why 的长度。
  • score 不是文笔分。它只是「交上来的证据里有多少条站得住」：一条声明都没交时 total: 0、score: 0（不是 100），别把 0 读成「全章不可信」；反过来，100% 也只代表证据真实，不代表它举的每一处都算违约。
  • 上下文隔离由宿主保证。任务书只能要求「给一个干净的上下文」；宿主若把写作用的对话一起塞给审计者，对抗性就打折——这是已知的外部依赖，插件管不到。
  • 口径对齐情况见上一节末尾（banned 豁免表、slop 题材静音、语义开关、空材料语义）：v7.2.0 发布前已收掉三处真实分叉，唯一保留的差异是「审计不加载参照集高频词豁免」（审计只会更严）。

十一类待办的判定来源

类型字符串是第一列这十一个中文词，没有其它取值。判定统一遵守文件头的硬约束：判定不出就跳过该类检查，绝不退化成默认词表兜底。

type判定来源典型触发 / 门槛
句式偏离六维中四个「写法维度」的出带判定（METRIC_TYPE 把 complexity / modifierDensity / actionDensity / hedgeDensity 统一映射到本类）该维相对偏差越出容差带，且绝对差值越过量级门槛：complexity 0.3（每句小句数）、modifierDensity 8、actionDensity 8、hedgeDensity 4（每千字点数）。低于门槛按「无量级差异」忽略
抽象度过高六维「抽象度」abstractDensity 出带同上，量级门槛 8（每千字点数）

locate：段落级 / 行号区间归因

现有分析引擎是段落级 / 句式级统计，没有行级归因。做法是先把正文切成段落并记下行号区间，逐段算指标，再把偏离最严重的若干段回映射成行号。三类问题的归因口径并不相同：

// ① 行号索引：换行先归一到 \n，1 起编号（与 novel_read 同口径） lines = text.replace(/\r\n?/g, "\n").split("\n") paragraphs = 连续非空行合并为一段 → 记 [lineStart, lineEnd]（空行视为段界） // ② 指标类（句式偏离 / 抽象度过高 / 留白异常）—— 按「段落是否同样出带」归因 for 每个章级出带的维度 v： if |v.value − v.mu| < 量级门槛 → 忽略该维度（不进清单） for 每个段落 p： （p.text.length ≥ 40 字才参与归因） if p 与全章「同向」偏离 且 judgeAgainstBaseline(测量(p)) 该维也出带： 收下 { p, 本段值, |σ| } 按 |σ| 降序取前 1 段（MAX_PARAGRAPH_ITEMS_PER_METRIC = 1） ← v5.1.0：同一维度只报最严重的这 1 段，其余同类段落不再逐段列出， 只在 summary 的计数里体现（旧版该常量为 3） 一段都没有 → 退化成一条「全章层面」项：lineStart = lineEnd = 0，severity 降一档、effort = 3 有段落项 → lineStart/lineEnd = 该段行区间，excerpt = 该段原文截 80 字，effort = 2 // ③ 字面类（禁用词 / 语用不符）—— 逐行扫描全部命中，行号给到「区间列表」（v6.5.0） + locateWord(rawLines, word)： + linesContaining(rawLines, word) ← core.js：全部命中行（文件内真实行号） + for 每一处命中： if isGuardedArtifact(word, line, at) → 记 guarded（丢弃该处） + else → 记 kept（该行进结果） + 全部命中都被守卫挡掉 → 该词不产生待办（挡掉的词在 summary 里披露） + ranges = mergeLineRanges(keptLines) ← core.js + rangesText = formatLineRanges(ranges) ← 「第2-10行，第52行」 + locate.lineStart = 首个区间起点，lineEnd = 末个区间终点（全部命中的超集） + locate.excerpt = 首个命中行的原文 trim 后截 80 字 + current = 「命中「词」K 处（位置：第2-10行，第52行）」；guarded > 0 时追加「另有 G 处疑似相邻巧合（邻接守卫忽略）」 + 档位：词长 ≥ 3 → hint 前缀【硬命中·3字以上】；词长 = 2 → 【待判·2字词】+「若读该行发现只是相邻巧合，可跳过本项」 + 仪式禁式（正则）→ 扫出全部命中，按 mergeLineRanges 汇总区间（上限 200 处），sample 取首个命中文本 + 称谓（XX小姐）→ 仍只报第一处（与 novel_continuity_check 同口径，prompt 全章统一） // ④ 情感过直 —— 段级命中计数；⑤ 衔接缺失 —— 用候选详情里「…」引号内的词做精确行定位； // 引号内取不到词 → 0/0 并在 hint 里说明「没有可精确定位的行」 // ⑥ 伏笔未回收 —— 跨章问题，正文里没有「哪一行」可指，一律 0/0 定位不到时：lineStart = lineEnd = 0，并在 hint 里说明这是全章 / 跨章层面的问题
宁可粗，也不给错的行号。指标类给的是段落区间（约 40 字起）而不是某一行，且段落必须自身也出带才被归因——否则会出现「全章留白偏高，却指向一段根本不带省略号的文字」这种自相矛盾的定位。做出这个取舍是因为错误的行号比宽泛的区间更有害：模型会照着一个错位置去改，改坏的是本来没问题的句子。凡归因置信不足，一律退到整段区间；连段都定不到时给 0 并在 hint 里说明。调用方应对 lineStart = lineEnd = 0 做显式分支，不要把它当作「第 1 行」。字面类同此口径：locate 的两端是全部命中区间的超集（首段起点 → 末段终点），精确到每一段的位置在 current / hint 的「位置：」里——要逐段核对请读那里，不要把 lineStart-lineEnd 当成一段连续文本。
字面类的定位与审计共用同一套判据（v6.5.0）。禁用词 / 客套禁词走 core.linesContaining + mergeLineRanges + formatLineRanges + isGuardedArtifact，与 novel_continuity_check 的用语审计逐字同口径——审计说「这[里正]是」不是问题，改稿台就不许再报一条待办（否则用户得在两个工具之间对着猜）。守卫判的是命中处紧邻的前/后一个字是否落在实证碰撞表（lib/lexicons/guards.js）里，只收有实证的字：错填会吃掉真命中（静默漏报），所以宁可少填。某个词的全部命中都被守卫挡掉时，该词不产生待办，并在 summary 的备注里如实披露「N 个词的全部命中经邻接守卫判为相邻巧合」。

行号的坐标系是绝对行号（1 起，含空行与标题行），与 novel_read 的 formatRead 一致，可直接把 lineStart 交给 novel_read 的 offset 读回上下文。换行先归一为 \n（\r\n / \r 都算一个换行），因此「字符偏移 → 行号」与「行数组下标」永远在同一个坐标系里。

落盘与改稿闭环

路径 = <root>/.novel-writer/audits/fix-plan-<书名>-<归一化章键>.json 归一化章键 = sanitizeSegment(normalizeChapterKey(chapter)) ← 例：「1」「01」「第1章.md」都归一为「第01章」；与 novel_summary 的章号键同源 文件内容 = { tool: "novel_fix_plan", version: "<插件版本，取自 package.json>", book, chapter { file, number, title }, chapterKey, generatedAt, baselineScope, summary, notes[], detectedIds[], items: [ { …9 个字段, state: "open"|"done"|"skip", stateAt: ISO|null } ] } ← 注意：落盘文件只有 baselineScope（没有 baselineMode）；返回体两个键都有 plan → 重新测量 + 原子写（先写 .tmp-<pid>-<时间戳> 再 rename，走在 withFileTx 文件事务内； 与上一次同 id 的项保留其 done/skip 状态与 stateAt） verify → 读该文件 + 对当前正文重算，逐项给出三态（本次不写盘） mark → 读-改-写该文件，只把 itemId 指定项的 state / stateAt 更新，并刷新 updatedAt

必然需要落盘：mark 与 verify 要跨调用记得「这一项处理过了」。文件按书名 + 归一化章键命名，且章键取自解析后的章文件（chapter="1" / "第01章.md" / "码头等船" 三种写法都归到同一份），避免同章不同写法各写一份、verify / mark 换个写法就「找不到清单」。落盘与 novel_continuity_check 的审计报告同处 audits/ 目录，文件名前缀 fix-plan- 与审计报告区分。plan 每次重新测量并整份覆盖该章的清单，但会按 id 把上一次的人工标记搬过来：N 项此前已人工标记 done/skip（状态已保留）会写进 summary。正文改动后 id 会随位置变化，旧 id 的标记自然失效（不会张冠李戴）。

落盘失败（目录只读 / 磁盘满 / 文件被占用）不抛错，本次清单仍内存返回；summary 明确追加保存失败原因，planFile 仍保留原本要写入的路径（该文件并不存在），调用方不会被误导为已保存。

verify 的三态

status含义detail 的形态
resolved（已解决）该条目在当前正文中已检不出——原来的问题项在本次重算的清单里既没有同 id 命中，也没有「同 type + 同一稳定问题身份（issueIdentity 非空且相等）」的兜底配对。可能是真改好了，也可能是这一段文本被改动后换了形态。「当前正文中已检不出该问题（已修复或该处文本已改动）」；若该条曾被人工 done / skip，尾部追加「（人工标记 done / skip）」
pending（仍待处理）问题还在。分两种命中路径：① id 精确命中（正文该处未动）；② 同 type + 同身份兜底——行号或数值变了但同类问题仍存在（要求 n.type === o.type 且 issueIdentity(n) 非空并等于 issueIdentity(o)；身份指纹由指标名 / 词条 / 类别 / 大纲子句等派生，不是只要同 type 就算），仍判 pending，并在 detail 里说明位置变化。①「问题仍存在：<current>」；②「问题仍存在（位置/数值已变化 → 现为第 N 行：<current>）」。人工标记不改变判定，只在尾部追加「（人工标记 done / skip）」——避免「标了完成但问题还在」被静默吞掉
new（本次新检出）本次重算清单里存在、但上一次落盘清单里没有配对上的条目——改稿最常见的副作用，必须显式报出来，否则「越改越偏」不会被发现。「本次新检出：<current>」

checked[] 的元素为 { id, type, status, detail }，其中 id 对 resolved / pending 保留旧清单的 id，对 new 是本次新生成的 id。summary 汇总三态计数（复测结果：已解决 X 项 / 仍待处理 Y 项 / 新检出 Z 项。）。清单文件不存在时不报错：所有本次检出的项都记为 new，summary 给出「未找到已落盘的改稿清单（<路径>）——本次按当前正文现算：…请先调用 buildFixPlan 生成清单。」

resolved 不等于「已回到带内」。判定口径是「这条待办在当前正文里还找不找得到」，而不是「该维度是否已落回基线带」。同一处改动可能让 A 项 resolved 的同时让 B 项变成 new；要确认整章是否回到带内，仍应跑一次 novel_style_check。

不误报

正常文本不产出待办项：各类型只在指标实际出带、命中禁用词 / 语用禁式或钩子确实未承接时才生成条目；全部合格时 items 为空数组，这是一次成功调用而不是失败。为了不误报，实现里设了五道闸：① 指标须同时越过相对容差带与绝对量级门槛；② 段落必须与全章同向偏离且自己也出带才被归因（同维最多 1 段，v5.1.0 起由 3 收紧到 1——同一维度只报最严重的那一段，其余同类段落由 summary 的计数体现，清单不再被同一维度的多段刷屏）；③ 无基线、无伏笔、无法判定章号时整类跳过；禁用词表为空（当前文化基准下无可扫的词）时同样跳过该类并说明原因，不另行兜底；④ 章节正文短于 40 字时跳过全部指标类检查（空文本的六维全是 0，与基线一比必然「处处出带」）；⑤（v6.5.0） 字面类命中先过邻接守卫（子串巧合不计），被守卫整词挡掉的词不产出待办并在 summary 里披露；已被本书用词豁免（allowWords）静音的词同样不产出。

清单长度有上限：单次最多 12 条（DEFAULT_MAX_ITEMS，v5.1.0 起由 40 收紧到 12），超出部分按排序截断，并在 summary 的备注里披露「待办超过 12 条，已按严重度从高到低截断 N 条（清单上限固定，先处理保留下来的高优先级项）」。上限收紧的用意是让清单可执行：一次抛出四十条，模型只会从上往下挑几条做，其余全部沦为空转；只留 12 条则每一条都是排序意义上最值得先动的，被截断的部分不是「漏掉了」，而是「这一轮先不管」——先按清单顺序处理保留下来的项，改完再跑一次 plan，原先被截断的项若仍成立会重新排进来（同一维度现在只报最严重的 1 段，因此回访时的清单也不会重新膨胀）。若清单接近或撞到这个上限，说明这一章的偏离是系统性的（通常该整段重写，而不是逐项修）。注意上限不由调用方传参放宽：buildFixPlan 内部虽有 opts.maxItems，但工具层固定传 {}，提示里不会再出现「可传 opts.maxItems」这类做不到的建议。

词表与语用来源（与开写包 / 审计同源）

改稿台的禁用词与语用规范不再只读用户登记的字段，而是与开写包、novel_continuity_check 共用同一个裁决点 core.resolveStyleRule(settings, chapterTexts)：

  • 禁用词 = 去重(用户登记的 bannedWords ∪ 该文化基准的默认表)。文化基准取 worldview 登记（cultureSource: "worldview"）；未登记时对本章正文跑 hintCulture 检测，判不出则落欧式默认表。旧行为：用户只登记了 basis 而未填 bannedWords 时，改稿台会写「未登记 worldview 禁用词表，禁用词检查已跳过」，一条禁词都不报；新行为：按文化基准合并默认表后逐词扫描。
  • 语用规范取合并结果：speechStyle 不再只取「单个条目」，而是合并全部 worldview 条目（数组去重、对象浅合并），与 novel_continuity_check 同口径。
  • 空词表的提示文案跟随实际基准：不再一律写「未登记 worldview 禁用词表」，改为「当前文化基准「X」的禁用词表为空，禁用词检查已跳过」。空表可能来自两种情况：显式登记 bannedWords: []，或「现代都市」基准本身没有文化禁用词——两者都会如实写明基准名称，便于判断。
  • 显式 bannedWords: [] 的语义：表示「我不要默认表」，此时确实不扫禁词（沿用既有语义），只用用户自己登记的表（为空则该类跳过）。
  • 逐词静音（v6.5.0）：worldview.allowWords = 本书用词豁免。登记后这些词在本书的禁用词与 speechStyle.honorBad 两路都不再报（过滤发生在同一个裁决点，所以改稿台 / 开写包 / 审计三处自动一致）。只作用于本书——不提供全局静音：全局静音会静默削弱所有书的覆盖，而人很难记得自己什么时候加过。用途是那些「在这本书里本来就是对」的词：修仙小说里的「修士」、中文历史小说里的「教堂」。登记方式（走真实工具入口，action: "add" 即可，不必先有别的 worldview 条目）：
    novel_settings add category=worldview name="用词豁免" allowWords=["修士"] → 写入 worldview 条目的 allowWords（净化：数组、去空、去重、每项 String、单项限长 40 字、最多 200 条） → core.resolveStyleRule 把这些词从 bannedWords 与 speechStyle.honorBad 里滤掉，并在 sources.muted 计数
    被静音的词不是被删掉：它仍留在词表里，别的书照常检查；本次清单的 summary 备注会写明「已按本书用词豁免静音 N 个词」——少报必须留痕，否则与漏报无法区分。

约束与边界

  • 不生成正文：hint 只给改写方向，anchor 只给可参照的原著样例；返回体里没有任何「改写后的句子」。插件不调用在线模型，也从不代替作者写字。
  • 只读正文，只写自己的清单文件：plan 不修改章节正文，落盘只发生在 <root>/.novel-writer/audits/ 下的 fix-plan-*.json；verify 连清单都不写，也不写指标缓存或旧版伏笔迁移文件；mark 只改该文件里的处置状态。
  • 取消会抛错，不会伪装成空结果：调用被中止时（AbortError）三个改稿动作一律向上抛，不落进任何降级分支；审计的三个动作同样如此——runAuditContracts 的每条契约 catch 里都先放行 AbortError，不把取消伪装成「契约未跑」——否则一次取消会返回「成功但清单为空」，被误读成「这一章没有问题」。
  • 行号可以被整段，但不会给错：指标类 locate 的最小粒度是段落；字面类（禁用词 / 语用）给的是命中行的区间列表（current / hint 里的「位置：第2-10行，第52行」逐段精确，locate 两端是这些区间的超集）；lineStart = lineEnd = 0 表示全章 / 跨章层面，需按分支处理。行号是绝对行号（与 novel_read 同口径），不随任何 offset 重编号。字面类还有一个前置过滤：命中处紧邻前/后一个字落在实证碰撞表里（如「这[里正]是」「[在下]面」）时该处不计入，全被挡掉的词不产出待办。
  • 档位只在 hint 前缀里，不改 type：type 是十一类固定中文词（e2e 契约），档位由 hint 的 【硬命中·3字以上】 / 【待判·2字词】 表达。待判档必须留「可以不改」的出口——2 字中文词当子串的概率天然很高（实测无辜句子里 14/15 条是误报），一律照改会把作者的正常用词改掉。
  • id 与正文位置绑定：先按 id 精确配对；位置变化后，仅按可确认的问题身份（禁用词、语用命中词、指标方向与摘录等）配对。只同类型不能确认是同一项时分别报告 resolved 与 new。
  • mark 的校验只有三条：itemId 非空、state ∈ {done, skip}、该章已落盘清单里存在该 id。任一不满足即报错；它不重新测量、不校验正文是否真的改了，标记纯粹是给下一次 plan / verify 看的处置台账。
  • 依赖已有材料，质量随材料走：禁用词 / 语用项依赖 novel_settings 的设定表，衔接项依赖上一章可读，伏笔项依赖 novel_plot 的登记质量。材料缺失时相应类别不产出待办（而不是产出猜测），原因写进 notes 与 summary，并随清单一起落盘。
  • 六维相关项可能整体缺失：需要至少 2 个基线章节（按全书 时即全书除本章外至少 2 章、全书合计至少 3 章；按部分 时即实际生效的基线章至少 2 章）才能估计作者自身波动；本章正文短于 40 字也跳过。此时句式偏离 / 抽象度过高 / 留白异常三类不产出，原因写进备注；style_check 的同一限制在此同样成立。
  • 首次调用需要测量本章：复用分章测量缓存（metricChaptersCached），已预热时成本很低；正文刚改过则要重算本章。
  • 优先级算法属经验值：severity 的分档阈值与 effort 的分级是规则给定值，不是从真实稿件学出来的；清单顺序应按实际改稿手感校准，而不是当作绝对权威。
  • 工具开关与引擎门禁是两道不同的闸：六个动作都要过 assertToolEnabled("novel_fix_plan")（工具级开关关闭时直接报错，可用 novel_sentence_config 重新开启）；此外 plan / verify 还要过「写作助手功能」总开关（关闭时拒绝执行，文案引导去侧边栏开启），mark 与审计的三个动作（audit / audit_brief / audit_verify）不受第二道闸约束——它们要么只改自己那份清单，要么只对契约（词表 / 登记表 / 结构）而不是对文风。
  • 审计只读：不改正文，也不落盘（v7.2.0）：audit / audit_brief / audit_verify 都不写任何文件（不生成报告、不写清单、不迁移旧版伏笔表——读登记表走 readOnly 分支），detail 不给改写建议。唯一的副作用是本地语义引擎的惰性加载（纯内存，块文本按哈希做内存 LRU，不落盘），没有新增任何落盘位置。
